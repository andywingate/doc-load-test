ℹ️ Multi-App Architecture - Unbalanced Thread Distribution

Separate Entra Identities: SO threads (10) and PO threads (5) use different Entra application credentials, isolating authentication and API quota management.

Thread Configuration: This test intentionally doubled SO threads from 5 to 10 while keeping PO threads at 5, testing whether SO throughput scales linearly with thread count.

Deep Insert Method: Each API call creates header + 3 lines in a single request, reducing API calls by 75% vs traditional approach.

Result: Doubling SO threads from 5 to 10 did NOT double SO throughput—only increased from ~2.1 to ~2.1 docs/sec (no gain). SO response times increased dramatically from ~2.3s to ~4.4s, indicating contention or backend bottleneck. Overall throughput (10.20/s) was lower than the balanced 5+5 configuration (11.09/s), confirming that SO processing is the bottleneck, not thread count.
